# Question validation and recovery

Read only before asking a candidate question; reuse while unchanged.

For application questions use the profile and saved answers already read with get_task_context at task start, plus the CV unless this is a technical CAPTCHA blocker. Do not call get_task_context again before asking. For missing-fact questions supply applicationBlocker.review={cvChecked: source/path and finding, missingFacts:[{key,gap,knownValueGap?}]}; key is a reusable fact category or application_specific, knownValueGap explains why an existing fact cannot resolve this exact required detail. For user_only access blockers no CV/profile review is required. For access blockers supply recovery={kind:form_entry, captcha or user_only,userActionReason,attempts:[{method,result}]}; form_entry requires two distinct safe attempts plus visualCheck={method:screenshot,result:empty or invalid,evidence}. AX/DOM may omit or redact contact values even when visually filled. A blank programmatic value is NOT proof of failed typing; inspect a fresh screenshot of the visible field first. Preserve the tab with markHandoff each turn, including unrelated search turns while any form is pending. For CAPTCHA use recovery.kind=captcha and captchaCheck={state,capability,evidence,limitation?}. First observe whether automatic verification clears; if the browser tool permits and exposes the challenge, try normal visible UI for at most two attempts and 60 seconds total, then verify the result. Ask only if a fresh check still says required and supported attempts failed, or explain the specific tool_disallowed/not_exposed limitation. No CV review is needed for this technical CAPTCHA gate. For any active application question, this call also saves the supplied checkpoint, blocked/uncertain state and reports the task atomically. Supply resumeContext here; do not save it in a separate call first. If completion.taskReported=true, end immediately without checkpoint/update/report calls. Never bypass browser-tool restrictions or site protections. user_only is only for login, MFA, required tool confirmation or other genuinely unavailable capability, never a workaround for failed typing. Do not retry submission. Inspect the entire accessible form before asking, collect all currently missing required facts and uncovered consents in one request (up to 10 fields), and reuse an existing unanswered question. Do not submit merely to discover required fields. Use browser_jev_inspect_form when available; unknown requiredness is not proof a field is optional. Tag reusable fields with factKey and consent fields with consentScope; never put factKey on consent or credentials. Structured reusable answers are included automatically in future get_task_context.reusableAnswers. Write the title, labels and help in concise Turkish, preserving exact site option values. Use fields to ask a short form: each field has a stable id, a single label, type (text/boolean/select/multiselect/date/number), optional help and required flag, and options for choices. Never bundle numbered subquestions in a label. Boolean fields start unanswered. First check profile, CV and saved answers; ask only facts still missing or genuinely conflicting. Never ask the user to reconfirm known facts. Job-specific questions require applicationBlocker: an actual required form field, browser access blocker, or consent not covered by policy. Quote the actual field label/required marker or observed blocker in evidence and explain in reasonUnknown what is missing after checking CV/profile/answers. A job-description requirement or fit assessment is NOT a blocker; do not interview the candidate to verify suitability. Leave optional unknown fields empty. Automatic submission is already authorized when profile authorization=submit and the source allows auto: never ask whether to submit. For uncovered_consent also provide consentScope (submission, recruitment_privacy, group_recruitment or other); already granted permissions cannot be asked again. After an answer, persist reusable facts via remember_candidate_fact. For a question about an open application form, supply jobId and resumeContext from the actual browser so the answer returns to that exact tab and step. Leave the incomplete tab open and use another tab for independent work. Read replies from get_task_context at the start of the next assigned task; use list_applications only for necessary cross-job history.
