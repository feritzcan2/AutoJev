# CAPTCHA and verification errors

A generic verification error is not proof of CAPTCHA. Inspect fresh visible evidence and allow an automatic check already in progress to settle. If it clears, continue. Otherwise follow the tool's reported capability and budget: at most two supported visible attempts and 60 seconds total from detection. A visible verification checkbox can appear in clickTargets with verification=true. Follow the executing provider policy, including at-action confirmation where required, before clicking it once. Do not repeatedly click it or solve image/audio/slider challenges. Those challenge interfaces remain unsupported. Use at most one screenshot when needed; do not ask Jev for an unsupported operation. Follow tool-required human handling; no external solvers, hidden-field writes, alternate accounts or bypasses.

For a still-required challenge use applicationBlocker.kind=access with recovery.kind=captcha, userActionReason, actual attempts and captchaCheck={state:required,capability:supported|tool_disallowed|not_exposed,evidence,limitation?}. State the specific unsupported capability; never fabricate an attempt. No CV review is required for this technical gate. ask_candidate saves the checkpoint, state and task report; end on completion.taskReported=true. Do not refill the form or repeat Submit. A site-side quota/exhaustion error cannot be solved by the candidate; report it without asking them to clear it.

A checked checkbox returns verification.state=cleared. Old inline “captcha required” text can remain from a prior attempt: do not ask the candidate to solve it again solely on that text. Reinspect the actual site step and any missing fields (including password confirmation) before continuing. Checkbox completion is neither account-creation nor application-submission proof. Do not repeat Submit when submission is uncertain; use the existing verification continuation workflow.
