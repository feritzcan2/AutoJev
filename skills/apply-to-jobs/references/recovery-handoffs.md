# Upload and account handoffs

- A selected file is not server acceptance. After upload, use the returned observation and inspect_form files evidence; if processing is ongoing, wait with a bounded fresh check. Reveal/scroll the observed continuation control; if the form is embedded use embeddedForms/frame_observe/frame_act in place only before any uncertain submission. Do not upload the same file again merely because the success label is offscreen. If no acceptance or continuation can be observed, preserve the draft and report exactly which evidence is missing.
- Never ask for a password in a JobLoop question or repeat a password supplied in a prior answer. For a required portal account, follow [portal-accounts.md](portal-accounts.md): use the secure profile credential request and password tool when supported; otherwise hand off the saved browser step. Existing saved/autofilled login may be used within authorization without reading credentials.
- An OAuth redirect_uri_mismatch is a site configuration failure, not a missing candidate fact. Do not repeat the same OAuth attempt. Inspect an observed alternative sign-in path; otherwise explain the site's failure and offer the account handoff or skip. Verify the displayed account matches the candidate before continuing; never switch to another person's account.
- For OTP invalid/expired, never reuse the rejected code. Use authorized Gmail verification as described in portal-accounts.md, or hand off if unavailable; reuse the same pending question, and recheck expiry on the next turn. Never treat a numeric reply as proof an application was submitted.
- For CAPTCHA, retain the same attempt and exact tab; describe it as verification pending, not submitted. If the tab has disappeared, report that explicitly rather than asking the user to click a nonexistent tab. Do not create another submission to recreate the challenge.
