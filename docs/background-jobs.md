# Background Jobs

Each candidate has one scheduled skill: choose a Markdown skill file, set the interval and enable it. The default is `skills/gmail-sync/SKILL.md`. The file is read afresh on every run, and can be previewed in the page. Provider, model and permissions inherit the candidate’s current agent settings by default. In Background Jobs settings, turn inheritance off to choose a separate provider, model, permission and reasoning level for this skill. Changes apply to the next run; existing sessions keep their launch settings.

Each run opens a fresh terminal agent in a stable app-owned workspace, executes the skill once, records its result and closes. Main conversations are not resumed or changed. Provider login/trust prompts are accessible in the task terminal. Runs have a ten-minute default timeout and can be stopped manually. Only one run per candidate is allowed at a time.

Scheduling requires the app to stay open. Missed intervals collapse into one run. A Gmail run blocked by missing access or account mismatch suspends automatic retries until a manual retry verifies access. Saving the interval does not remove the blocker. Other failures retry at the next interval. History and application mail results survive restart.

The Gmail connection controls discover the real app and its connection URL through Codex app/list, including paginated results. They open the provider-owned connection flow; no credentials are copied. After connecting, the check-and-retry button starts a fresh skill run. App availability does not establish Gmail account identity: the skill still verifies that before reading any messages. Claude requires its own Gmail MCP configuration.

The Gmail skill uses the terminal agent’s existing Gmail connector/MCP; JobLoop does not authenticate Google or fetch mail itself. The candidate’s profile email identifies the expected account (legacy mailbox selections are a fallback). The skill verifies account identity, searches application-related mail and records sourced results through candidate-scoped tracking tools. Missing access is reported as blocked. Ambiguous matches can be reviewed in the results list. Mail content is untrusted data; the skill only searches and reads, never sends or modifies mail.

The message composer starts an interactive skill conversation or promotes the active run to one. Interactive runs remain open after recording a result or asking for user help; use Stop to close them. A closed run is never presented as a writable live process: a new conversation receives its stored summary. Scheduled runs retain their normal completion and timeout behavior.
